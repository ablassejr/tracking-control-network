# Comprehensive Paper Review

**Paper:** "An Analysis and Simulation of Defending Tracking Control Neural Network for Known Affine Discrete-Time Nonlinear Systems Against Adversarial Attacks"
**Authors:** Ablasse Kingcaid-Ouedraogo (Mentee), Dr. Pavlo Tymoshchuk (Mentor)
**Pages:** 16 | **References:** 8 | **Figures:** 17
**Review Date:** March 29, 2026

---

## Executive Summary

The paper presents a discrete-time tracking control neural network, demonstrates its vulnerability to additive stochastic noise on the error channel, and proposes a voting-scheme defense using redundant processing units. A C++ port validates the MATLAB implementation. The mathematical development is sound and the paper follows a logical nominal-attacked-defended progression. However, **seven critical issues must be resolved before submission**, along with several structural and methodological concerns.

## 2. Major Issues (Should Fix)

### 2.1 No Conclusion Section

The paper ends abruptly after the runtime performance table (Section 4.3). There is no:
- Summary of contributions
- Discussion of limitations
- Future work (the paper mentions PGD attacks, other defense methods, and non-ideal channels as future work in passing, but never collects these)

This is required by virtually every journal and conference template.

### 2.2 Error Sign Convention Inconsistency

The paper defines `e(k) = x(k) - r(k)` (state minus reference) in eq. (4) and uses it consistently. However, `perturbed-block-diagram.tex:6` describes the perturbed error as:

```latex
$\tilde{e}(k) = (r(k) - x(k)) + \epsilon(k)$
```

This reverses the sign convention (reference minus state). Should be `(x(k) - r(k)) + epsilon(k)`.

### 2.3 Very Sparse Reference List (Only 8)

For a research paper addressing adversarial attacks on control systems, 8 references is insufficient. Missing coverage includes:
- Broader adversarial ML literature beyond Madry and Hajari
- Voting/redundancy in fault-tolerant control (TMR is decades old)
- Sliding-mode control theory (the actual control mechanism used)
- Discrete-time NN control beyond Tymoshchuk's own work
- Resilient control systems literature (Jedh is cited but more depth needed)

### 2.4 Introduction Lacks Explicit Contributions List

The introduction explains the problem and prior work but never clearly enumerates "The contributions of this paper are: (1)... (2)... (3)..." This is standard practice and helps reviewers assess novelty.

### 2.5 Wrong DOI for Reference [4] (Yan & Wang 2011)

`references.bib:69` assigns DOI `10.1109/ICARCV50220.2020.9305440` to a 2011 conference paper. The DOI resolves to a 2020 ICARCV paper, not the 2011 ICIST paper cited.

### 2.6 Inconsistent Section Numbering

`Main.tex:95` uses `\section*{Introduction}` (unnumbered) but the first numbered section inside `intro.tex:41` is `\section{A Discrete Time Tracking Control Neural Network}` which becomes Section 1. The introduction content sits outside the numbering scheme. Most journals either number the introduction (Section 1) or handle unnumbered introductions through their template class.

## 3. Methodological Concerns

### 3.1 Defense Is Trivially Correct

The voting scheme assumes clean processing units are **ideal** (`delta_i(k) = 0`). This means:
- `V_12(k) = 0` always (clean pair has zero disagreement)
- `V_{l3}(k) > 0` almost surely (any pair with the corrupted unit disagrees)

The minimum-variance pair selection deterministically chooses (1,2) at every timestep. The defense reduces to: "if two channels are perfect and one is noisy, pick the perfect ones." This is not a meaningful defense contribution. The CORRECTIONS_LOG shows there was a plan (item 47) to add clean-channel noise (sigma^2_s = 0.5) which would make the problem non-trivial, but this was reverted.

**Suggestion:** At minimum, add sensor noise to clean channels (sigma^2_s > 0) so the voting scheme must actually distinguish "slightly noisy" from "heavily attacked." This would make the theorem probabilistic rather than deterministic and strengthen the contribution.

### 3.2 Attack Model Is Very Simple

Additive i.i.d. Gaussian noise on the error channel does not model a strategic adversary. The paper acknowledges PGD as state-of-the-art but defers it. The Gaussian model is closer to sensor noise or random faults than to an adversarial attack. The paper could more honestly frame this as "disturbance rejection" rather than "adversarial defense" -- or at minimum discuss this limitation.

### 3.3 No Quantitative Defense Metrics

The defense is evaluated only visually ("Fig. 12 shows the state variables recover nominal tracking performance"). No quantitative metrics are reported:
- Mean/max tracking error under attack vs. defended
- Percentage of timesteps where the correct pair is selected
- Comparison of defended error magnitude to nominal error magnitude

### 3.4 Single Case Study

All results are demonstrated on a single CSTR system with fixed parameters. No sensitivity analysis (varying sigma, beta, number of channels) is provided.

## 6. Figures Assessment

**Strengths:**
- Gnuplot figures are consistently formatted with matching axis ranges and labels
- Color scheme (blue state, gold/yellow reference) provides good contrast
- k-axis (time steps) is consistent across all gnuplot figures

**Weaknesses:**
- MATLAB vs. C++ comparison figures (Fig. 14-17) have visually mismatched styles: MATLAB uses "x10^4" scientific notation on x-axis while C++ uses explicit tick labels (0, 5000, 10000...)
- MATLAB figures lack titles while C++ figures have them ("Conversion", "Temperature")
- MATLAB figures use dashed reference lines; C++ uses solid lines for both
- These visual differences weaken the "identical results" narrative
